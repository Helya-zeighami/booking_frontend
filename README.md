# نوبان — داشبورد مدیریت رزرو

یک داشبورد فارسی و راست‌به‌چپ برای مدیریت رزروهای کسب‌وکارهای خدماتی. این پروژه با تمرکز بر کیفیت محصول، دسترس‌پذیری، معماری قابل نگهداری و تعاملات واقعی ساخته شده است.

## امکانات

- نمایش آمار زندهٔ کل، امروز، تأییدشده و لغوشده بر اساس داده‌های Zustand
- جست‌وجو با نام و شماره تماس، فیلتر وضعیت و خدمت، مرتب‌سازی تاریخ و ساعت در هر دو جهت
- جدول دسکتاپ و کارت‌های خوانای موبایل
- ثبت رزرو با React Hook Form و اعتبارسنجی Zod
- جزئیات کامل رزرو و انتقال وضعیت کنترل‌شده
- تأیید جداگانه برای لغو رزرو و اعلان‌های دسترس‌پذیر
- رابط فارسی، ارقام و تاریخ بومی، RTL واقعی و منطقهٔ زمانی `Asia/Tehran`
- نوار پیشرفت مسیریابی با `@bprogress/next`
- ناوبری واکنش‌گرا و صفحات placeholder صادقانه برای ماژول‌های خارج از محدوده

## فناوری‌ها

Next.js 16 (App Router)، React 19، TypeScript strict، Tailwind CSS 4، اجزای مبتنی بر الگوی shadcn/ui و Radix UI، Zustand، React Hook Form، Zod، next-intl، BProgress، Lucide React و Sonner.

نسخه‌های دقیق در `package.json` و `package-lock.json` قفل شده‌اند. اسکریپت build از webpack استفاده می‌کند، چون اجرای Turbopack در محیط‌های sandbox که اجازهٔ bind کردن process داخلی PostCSS را نمی‌دهند شکست می‌خورد؛ این تصمیم رفتار محصول را تغییر نمی‌دهد.

## معماری

ساختار رابط از Atomic Design پیروی می‌کند:

- `src/components/atoms`: کنترل‌های پایه و variantهای CVA
- `src/components/molecules`: ترکیب‌های کوچک مانند StatusBadge و StatCard
- `src/components/organisms`: جدول، فیلتر، آمار، فرم و جزئیات رزرو
- `src/components/templates`: پوستهٔ داشبورد و ترکیب صفحهٔ رزرو
- `src/app`: routeها و تنظیمات سطح صفحه
- `src/features/bookings`: مدل دامنه، دادهٔ mock، schema، store و توابع خالص

اجزای Server به‌صورت پیش‌فرض استفاده شده‌اند و تنها بخش‌های تعاملی Client Component هستند. منطق فیلتر و آمار از JSX جدا است و یک مجموعه رزرو در Zustand تنها منبع حقیقت برنامه محسوب می‌شود.

## قوانین دامنه و اعتبارسنجی

وضعیت‌ها عبارت‌اند از `pending`، `confirmed`، `cancelled` و `completed`. انتقال‌های مجاز در یک محل تعریف شده‌اند:

- در انتظار ← تأییدشده یا لغوشده
- تأییدشده ← انجام‌شده یا لغوشده
- انجام‌شده و لغوشده وضعیت نهایی هستند

شماره تماس باید یک موبایل ایرانی ۱۱ رقمی با قالب `09xxxxxxxxx` باشد. تاریخ گذشته پذیرفته نمی‌شود و توضیحات حداکثر ۵۰۰ کاراکتر است. schema در `src/features/bookings/schemas` نگهداری و با `zodResolver` به فرم متصل شده است.

## بین‌المللی‌سازی و RTL

locale پیش‌فرض `fa` است. پیام‌ها در `src/messages/fa.json` قرار دارند و مسیرها با الگوی رسمی App Router در next-intl مدیریت می‌شوند. سند `lang="fa"` و `dir="rtl"` دارد؛ مقادیر ذاتاً چپ‌به‌راست مثل شماره و ساعت جهت مستقل دارند. تاریخ‌ها با `Intl.DateTimeFormat` و منطقهٔ زمانی تهران نمایش داده می‌شوند.

## اجرا

پیش‌نیاز: Node.js 22 یا نسخهٔ LTS سازگار.

```bash
npm install
npm run dev
```

سپس مسیر `http://localhost:3000/fa/bookings` را باز کنید.

## کنترل کیفیت و build

```bash
npm run lint
npm run typecheck
npm run build
npm start
```

## محدودیت‌ها

- backend، احراز هویت و همگام‌سازی چندکاربره در محدودهٔ این نسخه نیست.
- داده‌ها mock و در حافظه هستند؛ با refresh مرورگر به وضعیت اولیه بازمی‌گردند.
- صفحات مشتریان، خدمات، گزارش‌ها و تنظیمات عمداً placeholder هستند و قابلیت تکمیل‌شده را القا نمی‌کنند.
- تقویم ورودی از کنترل استاندارد مرورگر استفاده می‌کند؛ نمایش تاریخ پس از ثبت فارسی است، اما مقدار داخلی ISO/Gregorian باقی می‌ماند.

## تصمیم‌های اصلی

Radix فقط برای primitiveهای تعاملی حساس مانند Dialog و Dropdown استفاده شده تا مدیریت focus و صفحه‌کلید قابل اتکا بماند. variantهای بصری معنی‌دار با CVA تعریف شده‌اند. persistence عمداً اضافه نشده تا hydration و stale data غیرضروری وارد نسخهٔ بدون backend نشود.
